# 维护指南

## 修改入口

| 修改内容                                   | 首先查看                                |
| ------------------------------------------ | --------------------------------------- |
| 收益公式、价格曲线、概率、运势计算         | `js/game-rules.js`                      |
| 单项技能的解锁前置、价格参数和购买行为     | `js/skills.js`                          |
| 状态、存档、历史、音效、自动收益与点击反馈 | `js/game.js`                            |
| 技能节点位置、图标、连线、悬浮说明和拖动   | `js/shop.js`                            |
| 页面启动和语言按钮事件                     | `js/app.js`                             |
| 语言选择和文本参数                         | `js/i18n.js`、`js/localization-ui.js`   |
| 波浪门槛、速度、水汽范围                   | `js/wave-rules.js`                      |
| 波浪绘制                                   | `js/wave.js`                            |
| 运势表盘显示                               | `js/fortune.js`                         |
| 当前 Figma 布局和尺寸                      | `styles/ui-sync.css`                    |

| 模块晃动、悬浮动画                         | `styles/ui-motion.css`                  |
| 双语字体和排版                             | `styles/localization.css`               |
| 波浪及运势样式                             | `styles/wave.css`、`styles/fortune.css` |

`index.html` 明确列出加载顺序。保留普通脚本以支持直接打开本地文件；`game.js`、`skills.js`、`shop.js` 共享页面作用域，最后由 `app.js` 载入存档并启动。初始化必须放在这些文件都已加载之后。这里没有引入框架、打包或构建步骤。

技能树布局使用 `x`、`y`、`icon`、`parent`、`visible` 命名字段；图标偏移和连线端点保留 Figma 导出的精确坐标。修改图标时同时核对 `figma-ui-map.json`。

## 文案和资源

最终 Excel 是中文、英文文案的编辑入口。`locales/*.json` 和 `locales/copy.js` 都是生成结果：前者方便检查，后者支持直接打开 HTML。三份文件一起重建，不分别手改。新增技能先补文案编号、数值参数和技能配置，再补图标、布局及测试。

`node scripts/audit-assets.cjs` 检查页面引用、字体、直接加载和动态加载的 SVG，同时列出未引用 SVG。新增动态资源类型时，需要更新检查脚本中的对应推导；不能只凭全文搜索判断动态资源无用。

字体裁剪只在新增字符时需要。完整源字体不放进游戏资源；传入源字体路径，并按 `scripts/font-requirements.txt` 安装可选构建依赖。普通运行、文案生成和数值测试不依赖这些 Python 包。

## 存档和交互约定

- 保留现有存储键和旧存档校验/迁移，不能把兼容分支当作死代码删除。
- 收益统一记录实际进账；购买扣费不进入收入历史，累计收益不因购买减少。
- 购买和概率变化前先按旧状态结清帮手收益，避免时间片跨升级重复结算。
- 商店刷新必须保留按钮及图标节点，不能在按下和松开之间替换点击目标。
- `data-no-hit` 标记界面交互区域，防止操作按钮或表盘时额外获得 hit。
- 隐藏的状态元素和部分旧节点仍由逻辑或无障碍提示使用；删除前要检查事件和 DOM 查询。
- 样式按 `index.html` 顺序加载。Figma、自适应和本地化覆盖有明确顺序；修改时不要自动重排样式表或选择器。

## 检查与格式

运行 `node scripts/check.cjs` 检查语法、资源和数值；涉及 UI、存档或交互时启动静态服务器后运行 `node scripts/check.cjs --browser`。浏览器测试使用独立上下文，不修改玩家已有存档。

代码统一采用两空格和 LF，长行拆开。可选使用 Prettier 3.6.2，项目已提供配置；有 npm 的开发环境可以运行：

```sh
npx prettier@3.6.2 --write index.html "js/*.js" "styles/*.css" "scripts/*.cjs" "tests/*.cjs"
```

生成的文案、原始 SVG、字体及表格排除在自动格式化之外。不要为了缩短行数把源码压缩回单行。
